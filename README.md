# 暗渡 · Underpass

原生 macOS SwiftUI 服务通道工具，复用 v2rayN 当前选中的 Xray 节点。QQ 音乐与 Bilibili 均以声明式通道包安装，也可导入自己的 `.channel.json`。

## 使用

1. 在 v2rayN 中选中节点并保持其内核运行；关闭 v2rayN TUN 和其他接管默认路由的 VPN。
2. 打开 `outputs/暗渡.app`。如需更新正在运行的实例，先关闭通道并退出应用，再打开新构建。
3. 开启需要的服务，在 macOS 窗口中完成管理员授权。多个开关共用一个 TUN / Xray 会话，新增开关无需再次授权。
4. 等待行内显示“已开启”。这表示助手、路由与 DNS 规则已确认，不代表歌曲或视频已验证可播。首次开启后请重开应用或网页，原来已经建立的连接无法迁移。
5. 选择验证通道，打开对应应用/网页，或运行“测试连通性”。测试仅检查包中列出的 HTTPS 端点。QQ 音乐请播放未缓存歌曲；Bilibili 请实际播放、拖动进度、切换清晰度并检查图片。
6. 关闭一项撤销它的额外规则；重叠规则可能仍被其他开启的通道覆盖。关闭不是“强制直连”。最后一项关闭或移除后，恢复原系统代理并结束共享会话。

1.1 版采用双栏布局，默认 820 × 580 pt、最小 700 × 480 pt。左侧是独立滚动的紧凑通道列表，支持按名称/简介/ID 搜索，以及“全部 / 已开启”筛选。点击通道后，右侧同步显示“概览 / 连接 / 配置”；打开入口与测试按钮固定在详情顶部，连接记录增加不会把按钮推走。筛选和选择不会修改开关状态。导入位于顶部工具栏（⇧⌘I），⌘F 定位搜索，文件可直接拖到左侧列表。

窗口可缩放，支持系统/浅色/深色外观。关闭窗口不退出应用，可从 Window 菜单重新打开。退出应用会先请求关闭会话。下次启动恢复列表、顺序、外观、上次开关偏好，但所有通道的实际运行状态均从关闭开始，需手动开启。

## 通道管理

- “导入通道包”、拖入文件或用本应用打开 `.channel.json`，均先显示预览。点击“合并导入”后生效。
- 新 ID 追加且默认关闭；相同 ID 和内容跳过；新内容比较旧包、本地配置和新包后合并。未出现的通道不删除。
- 新规则去重加入，上游明确删除的旧规则会在预览列出；本地删除不被上游原样恢复。字段发生双向冲突时保留本地值。
- 同名不同 ID 要求用户选择另建或指定合并目标。同版本不同内容会提示差异；旧版本跳过，不自动降级。
- 每行“…”可查看/编辑本地 JSON、导出、排序、移除。包原始文本与本地修改分别保存；导出的是有效本地配置，不含节点信息。
- 移除运行中的通道会先更新规则再保存列表，其他通道保留；源文件不删除。支持撤销最近一次移除，撤销后保持关闭。
- 已移除预装项不会在启动或升级时自动装回。“恢复默认通道”也走增量预览，不替换用户列表。
- 校验失败不更改目录。运行配置先确认再落盘；落盘失败会回退运行规则。回退不能确认时关闭整个共享会话。

格式、匹配语义和示例见 [Docs/CHANNEL-FORMAT.md](Docs/CHANNEL-FORMAT.md)，机器可读约束见 [Resources/channel.schema.json](Resources/channel.schema.json)。包只描述已实现的能力，不是任意协议或脚本插件。

## 网络与恢复

- 只读 `~/Library/Application Support/v2rayN/binConfigs/config.json`。复制出站到独立 Xray，以随机认证 SOCKS 入口强制送到 `proxy` 出站。
- sing-box 管理 IPv4/IPv6 TUN、回环 mixed 代理、域名/进程/应用规则与 DNS。Bilibili 包覆盖网页、API、图片、视频 CDN 和短链接，采用公开维护源的相关子集，见包内 `sources`。未覆盖的第三方 CDN 可通过本地编辑增补。
- 域名命中与应用/进程命中取并集，优先送所选节点。Bilibili 不匹配整个浏览器进程，所以浏览器的其他站点保留原路径。
- 原系统代理为 v2rayN 回环端口时，未命中的系统代理流量继续交给 v2rayN；原来没有代理时，未命中流量直连。保留原先启用的代理协议及例外列表。不同端点代理、PAC/WPAD 暂不支持，会在开启前给出错误，不静默改写其逐站逻辑。
- `node` 策略的域名经节点访问固定 DoH（doh.pub / 1.12.12.12）；其他域名使用启动时检测到的原 IPv4 DNS。多个通道重叠时节点 DNS 优先。仅进程/应用规则不能保证其所有查询走节点 DNS。
- 本地规则集按文件更新，不使用 `/configs PUT` 冒充完整重载。每次更新用保留 `.invalid` 域名向同一个规则集对象发起无外网 DNS 探针，确认两个文件已加载，再清内核/系统 DNS 缓存并关闭受影响的可归属旧连接。
- 更新的两个文件并非内核级原子事务，短暂过渡和连接重建可能发生；异常时回退两个文件。浏览器自身 DNS、DoH、ECH、已有 IP 连接、QUIC 或未暴露的进程元数据可能妨碍归属，必要时重开应用/标签页。不会为开关关闭所有无关服务的连接，也不承诺零中断。
- root supervisor 监控父进程、12 秒心跳、子内核、节点文件和主网络服务/IP/DNS 变化。节点或网络变化会停止会话，要求用户手动重新开启，不自动沿用旧节点。
- 停止时先恢复仍由暗渡持有的代理字段，再结束子内核。用户或其他工具后来改过的端点保留。正常退出或 GUI 崩溃后的恢复路径已保留，但本次未进行真实特权故障注入。
- 若 supervisor 自身遭强制结束，可从管理菜单选择“恢复残留设置”，授权后按快照恢复属于暗渡的代理字段，并仅结束命令路径与该会话完全匹配的残留内核。若仍异常，请在系统设置 → 网络 → 当前服务 → 代理中检查，或让 v2rayN 重新设置系统代理。

复杂企业 VPN 的分域 DNS、多套 TUN 和所有网络配置并未实现透明兼容。原生核心来自本机 v2rayN，不自动更新。支持生成 Xray 配置的 VLESS、VMess、Trojan、Shadowsocks、SOCKS、HTTP 节点，最终以双内核校验结果为准。

## 数据与旧版兼容

新列表在 `~/Library/Application Support/Underpass/channels.json`，保留 `channels.backup.json`。会话位于同目录 `Sessions/`。目录 0700、含凭据配置 0600；正常停止后删除临时节点配置。异常断电后的配置也应视为敏感本地数据，不要上传整个 Sessions 或完整日志。

旧 `MusicRelay` 数据目录保留。旧版没有持久通道列表，首次使用会安装两个默认包并提示迁移；若发现兼容格式的旧列表则只读复制，旧会话不复制、不启动、不停止。应用和源码更名为 Underpass，但项目工作目录仍为 `MusicRelay`，以保持当前项目关联。

项目已使用 Git 管理，默认分支为 `main`，当前基线标签为 `v1.1.0`。旧源码快照、旧应用和 1.0 归档已移除；当前通道数据与偏好保留。源码、测试、资源和文档纳入版本控制，`outputs/`、`.build/`、设计缓存与运行会话不纳入仓库。

## 构建、检查与打包

Apple Silicon Mac、macOS 13+、Xcode command line tools、本机 v2rayN 的两个核心：

```sh
zsh build.sh
zsh test.sh --real-config
zsh package.sh
```

`build.sh` 首个参数可指定输出目录，默认 `outputs/`。依赖本机 `~/Library/Application Support/v2rayN/bin/{sing_box/sing-box,xray/xray}`，脚本不会下载或替换 v2rayN 文件。构建先在临时目录完成编译与校验，通过后再替换应用。替换失败会恢复原应用，替换成功即删除临时回退副本，不长期保留旧应用。构建包含本地 ad-hoc 签名及严格签名检查，不是 Apple 公证发行版。`-disable-sandbox` 仅用于当前 Swift 编译器的宏插件子进程，未移除应用运行时权限限制。

`test.sh` 编译并运行行为检查及真实核心回环测试；`--real-config` 增加当前节点的只读快照检查。受限执行器需要允许回环监听；测试没有 TUN、系统代理、管理员请求或外网访问。测试生成的节点快照在临时目录退出时删除。

产物：`outputs/暗渡.app`、`outputs/Underpass-macOS-1.1.0.zip`、`outputs/Underpass-Source-1.1.0.zip`。源码归档使用白名单，不包含运行数据、旧备份、缓存、二进制核心或应用。许可见 `THIRD_PARTY_NOTICES.txt`。

1.1 布局验证见 [Docs/VALIDATION-1.1.md](Docs/VALIDATION-1.1.md)，此前内核验证证据及未实测范围见 [Docs/VALIDATION.md](Docs/VALIDATION.md)。QQ 音乐旧版已由用户实测跑通；新版尚需现场管理员 TUN 启停、真实代理恢复、公司网络歌曲与 Bilibili 播放验证。

## Git 使用

这是本地仓库，尚未配置远程地址。常用命令：

```sh
git status
git log --oneline --decorate
git diff
git switch -c feature/your-change
```

需要取用某次提交的源码时，可使用独立目录，不必在当前工作目录保留整套副本：

```sh
git archive v1.1.0 -o /tmp/Underpass-v1.1.0.zip
```

发布归档仍由 `package.sh` 生成，不包含 `.git`、运行数据或构建缓存。
